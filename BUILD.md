# Building

Requirements: Node 20+ (CI uses 22), Python 3, and for Android: JDK 21 (Capacitor 7), Android SDK.

## Web / PWA
```bash
npm install
npm run icons
npm run lint && npm test
npm run serve
```
Serve `www/` over HTTPS (or localhost) on any static host. Use `_headers` (Cloudflare Pages/Netlify) to get real security headers including `frame-ancestors`; GitHub Pages cannot set headers.

## Android debug APK (GitHub Actions)
1. Push to `main` or run **Actions → CI → Run workflow**.
2. When the run is green, open it and download the artifact **BreachGuard-debug-apk** (zip containing `app-debug.apk` and its `.sha256`).
3. On the phone: unzip, allow "install unknown apps" for your file manager, open the APK. A debug APK is signed with a debug key and is for testing only.

## Android locally
```bash
npm install && npm run icons
npx cap add android && npx cap sync android
npm run android:harden
cd android && ./gradlew assembleDebug
```
Output: `android/app/build/outputs/apk/debug/app-debug.apk`. The `android/` folder is generated and git-ignored; `scripts/android_harden.py` applies and verifies the manifest policy.

## Release signing
Not configured. Create a keystore yourself, keep it out of Git, and inject it via CI secrets. Never commit `*.jks`/`*.keystore`.

## Known gaps
- No `package-lock.json` yet. CI uploads the generated one as an artifact; commit it, then switch to `npm ci`.
- GitHub Actions are pinned by version tag, not commit SHA. Dependabot is configured to update them.
- PNG icons are generated by `scripts/gen_icons.py` (binary files could not be committed through the tooling used). Run `npm run icons` and commit `www/icons/` if you prefer them in Git.
